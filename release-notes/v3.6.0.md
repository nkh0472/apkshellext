# ApkShellext2 3.6.0

Stage 2 dependency modernization release. Four dependency groups are gone, the deployment tree shrinks by 30.9%, and every rendered icon is byte-identical to 3.5.1 on the 87-sample corpus.

## Highlights

- Zip containers are read with the BCL `System.IO.Compression.ZipArchive`; the source-embedded SharpZipLib submodule is deleted and every reader now goes through one capped `ZipSafety` layer.
- ExCSS and the unused SVG text, filter, extensibility and raster-image subtrees are removed; rewriting the parsers on plain strings drops the System.Memory facade family.
- Deployment tree 3,392,793 B (32 files) → 2,344,225 B (27 files), 7z 1,028,354 B → 746,997 B, dll 1,573,888 B → 1,165,312 B.
- No behavior change: 87/87 sample icons are pixel-identical (SHA-256) and all 15 malformed-package probes still exit cleanly with no escaped exception.

## Dependencies

- **SharpZipLib 1.4.2 → BCL `ZipArchive`.** The source-embedded submodule (428 files, 28.2 MB) is deleted. The APK, AAB, APPX, APPXBUNDLE, IPA and split-bundle readers all open archives through `ZipSafety`, which keeps the per-entry hard cap plus the 1032:1 compression-ratio cap; `OpenZip` additionally rejects a central directory with more than 65,535 entries. The only remaining SharpZipLib-namespace code is a 286-line zlib/CRC-32 shim required by the pinned PNGDecrush source (RFC 1950 framing, Adler-32, IEEE CRC-32).
- **ExCSS 4.2.3 removed.** The product never passed a stylesheet to `SvgDocument.FromSvg` and never emitted `<style>` elements or `style=` selectors, so the CSS cascade was dead code. The minimal `style="name:value;..."` attribute passthrough stays; full CSS is documented as unsupported in `ApkShellext2\SVG\NOTICE.txt`.
- **SVG vendor subtrees trimmed.** Text rendering, Filter Effects, Extensibility (`foreignObject`) and raster `<image>` elements are deleted (85 files, about 5,100 lines) after confirming that no product, test or generator reference remains. The `ResolveExternalImages` safety switch is retained but no longer consumed on the SVG side.
- **System.Memory facade family removed.** `System.Memory`, `System.Buffers`, `System.Runtime.CompilerServices.Unsafe` and `System.Numerics.Vectors` package references plus the `FacadeResolver` assembly-resolution redirect are gone; the nine SVG parser files now walk a `TextSlice` over plain strings. The main dll references framework assemblies only, so the published layout goes from 13 root files in 3.5.1 to 8.

The 7z size moves by a few hundred bytes between runs because archive timestamps are not normalized. The deployment tree is 8 root files (the dll, five .bat scripts and two libwebp dlls) plus 19 satellite resource assemblies.

## Security

- One containment layer: every zip-derived read, including nested `.appx` and `.apk` members, goes through `ZipSafety`, so entry-name decoding, size caps and error handling cannot drift between readers.
- New 65,535-entry cap in `OpenZip`: the count is read from the central directory, recorded in the error log, then rejected with `InvalidDataException` before any entry is touched. 65,535 is the non-zip64 end-of-central-directory maximum and the check stays O(n) bounded.
- Per-entry reads keep the hard cap, the 1032:1 compression-ratio cap and the 1 MiB rule; a declared size of 0xFFFFFFFF is treated as unknown instead of 4 GiB.
- Failures still land in `%PUBLIC%\apkshellext-error.log` (1 MiB rolling) and still never escape into Explorer.

## Compatibility

- The `install.bat`, `install_user.bat` and `uninstall*.bat` contracts are unchanged: same dual-bitness registration, same per-user option, same offline sweep of legacy COM entries.
- The registry layout is unchanged (`HKCU\SOFTWARE\ApkShellext2` for settings, the same HKCR registration entries).
- .NET Framework 4.8, the 19 UI languages and both 64-bit and 32-bit Explorer hosts are unchanged.
- No new runtime dependency ships: the deployment no longer needs facade dlls, and libwebp 1.6.0 is unchanged.

## Known issues

- A `.appxbundle` whose inner `.appx` entry is deflated still fails with `NotSupportedException: zip containers must be opened from a seekable stream`; stored inner packages read fine (known since stage 0, out of scope here).
- On Windows 11 the shell does not call the `.appx`/`.appxbundle` icon handler; those files show the system package icon (the context menu and infotip still work).
- A WebP image over the decode limits is rejected with a debug-log line only; it does not produce an error-log entry.
