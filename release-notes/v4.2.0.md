# ApkShellext2 4.2.0

## Highlights

| Change | Detail |
|---|---|
| CSV reports more of the package | `MinSdk`, `TargetSdk`, `Debuggable`, `Packer`, `Verdict` and `Evidence` are new columns; the SDK levels and the debuggable flag come from the same manifest walk the icon uses, the packer from the APK signing block. |
| `.apks` reports the minimum SDK | A split bundle with `metadata/toc.pb` now reports the lowest `minSdk` of its variants instead of only the base manifest value. The walk is bounded (2 MiB entry, depth 8, 4096 fields per message) and a broken chain falls back to the manifest. |
| Configuration splits can carry the icon | A base package whose manifest icon lives in a `split_config.*.apk` now shows it, choosing the highest density split first; a base package that already renders an icon is untouched. |
| Locale names are guarded | Resource locale names that are not ASCII are rejected; tests pin the guard, including the `0xAD`, `es-¤$` shapes seen in the wild. |
| Verdict column | `Info` / `Suspicious` (repacking marker or debuggable manifest) / `Tampered` (the container contradicts its own manifest: the named icon is not in the package, or the manifest names an id while the package carries no `resources.arsc`). |

## Upgrade notes

- Replace the whole folder, not just `ApkShellext2.dll`: the satellite assemblies must carry the same version as the main DLL, otherwise Windows silently falls back to English.
- A package whose manifest names an icon by resource id but carries no `resources.arsc` used to be reported as `unreadable`; it is now `ok` with `Verdict=Tampered` and `Evidence=resources.arsc is missing`, so the name, package and icon still show up.
- `Verdict` is a hint, not a security verdict: no signature chain is verified and no reputation feed is consulted.

## Known issues

- The `Verdict` column only fills in for `.apk` and `.apks`; other container types report an empty verdict.
- `Packer` recognises Walle, ByteDance/Frosting, PackerNG and VasDollyV2; other packers report an empty value.
- The `duplicate resource id` heuristic was removed in this release: a legitimate app can ship two packages that define the same type/entry ids for the same configuration, which made the hint flag normal packages.
