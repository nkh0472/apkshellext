# ApkShellext2 4.1.1

A translation release: every string the 3.x and 4.x commands added is now present in all 19
languages, and a test keeps the satellite resource files in step with the neutral one from now
on.

## Highlights

- **No more English inside a localized menu.** The copy submenu (`Copy info`, `Copy File Path`,
  `Copy App Name`, `Copy Package Name`, `Copy Version`), the `Check the hash on VirusTotal`
  entry, the folder picker title and the rename-variable descriptions were added to the neutral
  resource file only, so every non-English UI showed those entries in English. All 19 satellites
  now carry translations for the 24 missing keys (21 for Simplified Chinese, whose three
  existing translations were kept).

- **A test guards the gap.** `ResourceTranslationTests` reads the resource files from the
  repository and fails when a neutral key is missing from any satellite, when a satellite key no
  longer exists in the neutral file, or when a value is empty. The next command that adds a
  string cannot ship half-translated.

- **The Rename and info tip pages of Preferences now describe their variables in the UI
  language** as well, including the per-variable descriptions under the list.

## Upgrade notes

- `update.bat` copies the whole deployment folder, so an existing installation picks the new
  satellite assemblies up. If you replace only `ApkShellext2.dll`, keep the language folders in
  step with it: a satellite whose assembly version does not match the main assembly is rejected
  by the runtime and the UI silently falls back to English.

## Known issues

- Windows 11 22H2+ uses the modern `IExplorerCommand` menu; Windows 10 and *Show more options*
  use the classic one. Both keep the same entries.
- Thumbnails are offered for `.apk` only; a thumbnail older than the file may be served from the
  Explorer cache until the cache is cleared.
- `update.bat` leaves its own script in the installation folder after a rollback of an in-place
  upgrade; deleting it is harmless.
- Code signing is not applied to the release binaries: sign the package yourself if your policy
  requires it.
